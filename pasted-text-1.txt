# 三、本轮必须修复的 P0 问题

## 任务 1：修复多文件批次无法生成综合目录

当前问题：

`runImportJob()` 在当前文档还是 `MAPPING` 状态时调用 `finalizeImportBatch()`，随后才把当前文档改成 `READY_FOR_REVIEW`。

而 `finalizeImportBatch()` 要求批次所有文档都已经是：

```text
READY_FOR_REVIEW
APPLIED
```

所以多文档批次实际上不会进入综合生成。

### 必须修改为

单文档处理顺序：

```text
解析文档
→ 生成该资料独立目录
→ 生成该资料独立知识图谱
→ 将该文档标记为 READY_FOR_REVIEW
→ 再调用 finalizeImportBatch(batchId)
```

`finalizeImportBatch()` 必须满足：

1. 只有批次所有未删除文档均成功完成，才生成综合目录。
2. 同一个批次只能有一个执行者成功进入 `COMBINING`。
3. 综合目录成功后，批次进入 `READY_FOR_REVIEW`。
4. 任意文档失败时，批次进入 `FAILED`，不得展示综合目录保存入口。
5. 重复恢复任务或重复调用不能生成多次综合目录。
6. 已保存的批次不能重新生成并覆盖原目录。

### 页面要求

批次存在时：

```text
只能使用 batch.generatedOutline
```

禁止使用：

```text
batch.generatedOutline ?? job.generatedOutline
```

批次综合目录还没有完成时，页面只能展示：

```text
正在综合分析多份资料
```

不得回退展示某一份文档的目录，也不得出现“保存课程目录”。

后端保存接口必须校验：

* 批次存在；
* 批次状态为 `READY_FOR_REVIEW`；
* 批次 `generatedOutline` 非空；
* 批次所有未删除文档都已完成；
* 当前批次尚未保存；
* 用户提交的目录基于该批次当前版本。

否则返回明确的 409 或 400，不能依赖前端拦截。

## 任务 2：增加真实多文档批次集成测试

现有 `importPipeline.test.ts` 只验证模型未配置失败，没有验证成功的多文档批次。

必须新增真实测试，至少覆盖：

### 测试 A：两份文档综合成功

```text
创建课程
创建一个批次
创建两份文档任务
分别完成解析、资料目录和知识图谱生成
第一份完成后批次不能 READY_FOR_REVIEW
第二份完成后批次生成且只生成一次综合目录
批次最终为 READY_FOR_REVIEW
```

断言综合生成调用接收到两份资料内容，不能只包含其中一份。

### 测试 B：批次未完成不能保存

一份完成、一份仍处理中时调用保存接口，应返回错误，课程目录不改变。

### 测试 C：批次并发收口

同时完成最后两份文档时，只允许一次进入 `COMBINING`，只能生成一份综合目录。

### 测试 D：失败批次

其中一份失败后，批次必须是 `FAILED`，不能保存单文档目录冒充综合目录。

不要把这些关键逻辑全部 mock 掉。可以 mock AI 模型返回稳定结果，但必须使用真实数据库状态流转。

## 任务 3：课程目录保存改为增量更新，保留 ID

当前两个保存接口仍然执行：

```text
deleteMany chapters
重新创建全部 chapter / lesson
```

这是禁止的。

会造成：

* 章节和课时 ID 全部变化；
* `Resource.lessonId` 被置空；
* 学习进度、笔记和其他课时引用失效；
* 上游 AI 快照中的章节 ID 失效。

### 必须改成增量更新

客户端提交现有章节、课时时必须携带数据库 ID。

规则：

```text
已存在且仍在提交中的章节 → update
新临时 ID 的章节 → create
数据库存在但提交中明确删除的章节 → delete
章节下已存在课时 → update
新课时 → create
明确删除的课时 → delete
```

要求：

1. 未修改章节和课时的 ID 必须保持不变。
2. 修改标题、简介、排序只更新字段。
3. 删除课时前明确处理或保留关联资料。
4. 删除章节时，若包含已被资料、学习进度、笔记等引用的课时，必须给出明确策略：

   * 阻止删除并提示引用情况；或
   * 经确认后级联处理。

   禁止静默解除关联。
5. 保留现有 `outlineVersion` 乐观锁。
6. 两位教师同时保存时，后提交者收到 409，不得覆盖。
7. 导入批次首次“保存课程目录”和后续“编辑→保存修改”必须复用同一套增量同步服务，不能维护两份不同实现。

建议抽出统一函数，例如：

```text
syncCourseOutline()
```

首次保存时，如果当前课程没有目录，可以全部创建；如果课程已有目录，也必须安全增量合并或明确替换策略，不能直接删除重建。

## 任务 4：资料章节必须映射到真实原文

当前选择资料具体章节后，AI 教案使用的是：

```text
JSON.stringify(生成目录章节)
```

这不是章节原文，必须修复。

### 目标数据

每份解析资料必须持久化稳定的章节结构，例如：

```ts
{
  id: "稳定章节ID",
  title: "第一章 人工智能概述",
  order: 1,
  text: "该章节对应的真实文档原文……",
  startOffset?: 0,
  endOffset?: 1580
}
```

具体使用 JSON 字段还是独立数据表，可以根据现有架构选择，但必须满足：

1. 章节 ID 稳定，不能只使用 `chapter-${order}`。
2. 保存真实章节正文，不是生成目录摘要。
3. 每个章节必须能追溯到所属 `DocumentImportJob`。
4. 重新解析资料后，要能识别旧选择是否失效。
5. AI 教案选择整份资料时使用完整解析原文。
6. 选择部分章节时，只使用所选章节的真实正文。
7. 如果无法从文档标题准确切分，要保留合理降级：

   * 标记章节映射置信度；
   * 允许整份资料选择；
   * 不得用 AI 目录 JSON 冒充正文。

### API 校验

AI 教案生成接口必须验证：

* 资料属于当前课程；
* 资料未删除；
* 资料已解析完成；
* 章节 ID 属于该资料；
* 章节正文存在；
* 不接受客户端伪造章节标题或正文。

`inputSnapshot` 中保存：

```text
课程目录版本
资料 ID
资料版本或更新时间
章节 ID
章节标题
```

保证后续可追溯。
